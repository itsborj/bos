## Deployment Model

Single-tenant per VPS. Each org gets their own deployment. Code is identical across all instances; only `.env`, domain, and data differ. The product shipped is a Docker image + compose file, not a shared SaaS service.

```
┌─────────────────────────────────────────────────┐
│  GitHub repo                                     │
│  git push → GitHub Actions builds image          │
│           → pushes to GHCR (api:latest or :v1.x) │
└─────────────────────────────────────────────────┘
              ↓ Watchtower polls + pulls
┌─────────────────────────────────────────────────┐
│  Org A VPS (e.g. Hetzner, $6/mo)               │
│  /opt/bos/                                       │
│    docker-compose.prod.yml   ← pulled from git   │
│    .env                      ← unique per org    │
│    Caddyfile                 ← unique domain     │
│    update.sh                 ← manual trigger    │
│                                                  │
│  services: db, api (ghcr image), web (nginx),   │
│            caddy, watchtower                     │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│  Org B VPS — same image, different .env          │
└─────────────────────────────────────────────────┘
```

---

## Key Decisions

**Plugins are baked into the Docker image.** We are the plugin developer. No plugin registry or live delivery mechanism needed. Updating a plugin = build a new image tag = Watchtower picks it up on each VPS automatically.

**Caddy replaces dev nginx.** Auto-provisions Let's Encrypt TLS. No certbot, no manual cert renewal.

**Watchtower solves "dev is offline."** Push a commit from anywhere → GitHub builds + pushes image → Watchtower pulls on each VPS within 5 min. No SSH required for code/plugin updates.

**Config changes (`.env`, domain) always require SSH.** Unavoidable for security.

## Files to Build

### `api/Dockerfile.prod`
- Remove `--reload`
- `uvicorn main:app --host 0.0.0.0 --port 8000 --workers 2`
- No volume mounts — code baked in

### `web/Dockerfile.prod`
- Stage 1: `npm ci && npm run build`
- Stage 2: nginx serves `/dist`

### `docker-compose.prod.yml`
- No `./api:/app` or `./web:/app` volume mounts
- API uses GHCR image tag, not local build
- Caddy instead of dev nginx (auto HTTPS)
- Watchtower service added
- `POSTGRES_PASSWORD` from env (not hardcoded `bos`)

### `Caddyfile.template`
```
yourdomain.com {
  reverse_proxy /api/* api:8000 { header_up Host {host} }
  reverse_proxy /* web:80
}
```
Each org fills in their domain.

### `.env.prod.example`
```
# Generated by setup.sh — never commit the actual .env
POSTGRES_PASSWORD=
API_SECRET_KEY=
ENCRYPTION_KEY=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=https://YOUR_DOMAIN/api/social/gmail/callback
# GOOGLE_CALENDAR_REDIRECT_URI is not required — auto-derived from GOOGLE_REDIRECT_URI
# (replaces /social/gmail/callback → /social/google-calendar/callback)
# Set explicitly only if your domain routing differs from the Gmail callback pattern.
FRONTEND_URL=https://YOUR_DOMAIN
PLATFORM_OPENROUTER_KEY=    # optional
```

> **Local dev note:** Set `FRONTEND_URL=http://localhost:8090` (the Docker nginx HQ port).  
> `http://localhost` (port 80) has no listener by default — the host nginx config rejects  
> unmatched hosts with 444 and has no `localhost` server block. Using port 80 locally  
> causes OAuth callbacks and calendar widget links to silently fail.

### `setup.sh`
One-time VPS setup: generates secrets, creates `.env` from template, runs initial migrations.

### `update.sh`
```bash
#!/bin/bash
git pull
docker compose -f docker-compose.prod.yml pull api
docker compose -f docker-compose.prod.yml up -d api
docker compose -f docker-compose.prod.yml exec api alembic upgrade head
```
Run manually to force an update outside of Watchtower.

### `.github/workflows/release.yml`
- Trigger: push to `main` or version tag `v*`
- Builds `api/Dockerfile.prod` → pushes to `ghcr.io/you/bos-api:latest` and `:v{tag}`

## Plugin Update Flow

```
1. Edit api/plugins/*/module.py locally
2. git push → GitHub Actions builds new api image
3. Watchtower pulls new image on each VPS (within ~5 min)
4. API restarts with updated plugin — no SSH, no manual steps

Exception: if a plugin adds a new env var or DB migration,
SSH is required to update .env and run alembic upgrade head.
Document these in release notes.
```

## Per-Deployment Config

Each org's VPS lives in `/opt/bos/`:

```
/opt/bos/
  docker-compose.prod.yml   ← git pull to update
  .env                      ← unique, set once, never touched again
  Caddyfile                 ← unique domain
  update.sh                 ← manual force-update
  backups/                  ← pg_dump cron target
```

Track deployments in a private `deployments/` directory (not in this repo):
```
deployments/
  org-a.md    ← VPS IP, domain, notes, last updated
  org-b.md    ← VPS IP, domain, notes, last updated
```

## Implementation Order

1. `api/Dockerfile.prod` — remove `--reload`, bake code in
2. `web/Dockerfile.prod` — build step + nginx
3. `docker-compose.prod.yml` — Caddy + Watchtower
4. `.env.prod.example` + `setup.sh`
5. Test full stack on one real VPS end-to-end
6. `.github/workflows/release.yml` — image build + push to GHCR
7. Per-org setup README or Notion page

## Google OAuth Setup (per deployment)

BOS uses a single Google OAuth 2.0 app for all Google integrations (Gmail, Google Ads, Google Calendar). Each deploying org creates their own OAuth app in Google Cloud Console and sets the client ID/secret in `.env`.

**Required Authorized Redirect URIs in Google Cloud Console:**

| Integration | Redirect URI |
|---|---|
| Gmail | `https://YOUR_DOMAIN/api/social/gmail/callback` |
| Google Calendar Booking | `https://YOUR_DOMAIN/api/social/google-calendar/callback` |

`GOOGLE_CALENDAR_REDIRECT_URI` does not need to be set in `.env` — it is auto-derived from `GOOGLE_REDIRECT_URI` by replacing the path suffix. The two URIs must both be registered in Google Cloud Console under the same OAuth client.

**Required OAuth Scopes (request in Google Cloud Console):**

| Scope | Used by |
|---|---|
| `https://www.googleapis.com/auth/gmail.send` | Gmail send, Calendar booking confirmations |
| `https://www.googleapis.com/auth/gmail.readonly` | Gmail inbox |
| `https://www.googleapis.com/auth/calendar` | Calendar booking (read/write events + FreeBusy) |
| `openid email` | All Google OAuth flows (user identity) |
